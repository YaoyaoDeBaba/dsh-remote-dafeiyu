# 肥鱼拉群（dafeiyu-groups）

## 它是什么，不是什么

群是一层**给用户看的记录**：用户能在群面板里看到谁 @ 了谁、说了什么。
而你（agent）**看不到群里的整段消息**——插件只把你被 @ 的那条单独送进你的会话，
里面带「本轮协作对象」。所以：群里其他人的话你不知道，除非对方点名给你。

## 你什么时候会用到

- 收到「【入群通知 · 群名 · 群 id】」：你被拉进群了，名单在通知里；
- 收到「【群 群名 · 群 id · 来自 用户/某会话】」：有人 @ 你，正文 + 本轮协作对象都在里面。

## 三个动作

1. **把结论同步进群**：`group_post(groupId, text)` —— 只入记录，不打扰别人。
   想点名让谁看，加 `to: [对方短号或会话 id]`，这句话会**单独投给那几个人**。
2. **补上下文**：`group_read(groupId, limit=20)` —— 看最近记录（你别每轮都读，很占上下文）。
3. **建群 / 拉人 / 退群**：`group_create(name, sessionIds)`、`group_invite(groupId, sessionIds)`、
   `group_leave(groupId)`。

## 回复格式：首行写摘要（2026-11-19）

你在群里说的话，用户看到的**只有摘要**（全文收在记录里，点开才看）。所以每条 group_post：

```
摘要：一句话说清结论（不超过 40 字）

正文：改了什么、要谁配合、卡在哪。
```

- 没写 `摘要：` 首行时，群里会退化成取正文**前 25 个字**——通常很难看，别赌。
- 摘要里别放代码、路径、长 id，用户是扫一眼的。

## 群里的人（成员身份）

每次投递都会带一行成员名单，形如 `👑产品经理（总负责人）、前端主程（页面）、后端主程（接口）`。
括号里是用户给的身份，**按身份判断该找谁**，不用猜。

## 别被说明书淹掉（第二次起只给极短头）

第一次收到群消息时会带一份完整用法（就是本文档的摘要版）；之后每条只有：

```
【群 群名 · 来自 谁】
正文
成员：…｜群主 …
```

工具怎么用要记住（或者回来 group_read `dafeiyu-groups` 这篇）。

## 说话的分寸（重要）

- 每条 `group_post` 都可能进别人的上下文：**只说对方必须知道的**（接口变了、字段改名、谁在等谁）。
- 单条 4000 字上限；长内容写进文件、在群里给路径。
- 不确定要不要说就别说。群不是聊天室，是同步通道。
- **说人话、说到点上**（2026-11-24）：一条消息只装一个新信息或一个请求，删掉所有铺垫。
  **禁止口头禅与客套**——「分析得很到位」「你说得对」「这个我认」「感谢反馈」「我先说明一下」「总结一下」「如上所述」；
  也别夸对方、别复述对方刚说过的话、别写自我检讨。这些都不算信息，只会逼对方再回一条。
  发之前自检，**两种合格形态占一样就能发**：① **请求**——谁要做什么 / 改哪个文件 / 怎么算完成；
  ② **结果**——可核对的新信息：结论、数值、判据通过数、版本或 commit、状态变化（带时间和来源）。
  两样都拿不出来的（只剩感受、复述、客套、确认）才不该发。**结果回复不用硬凑「改哪个文件」**，报了结论和数字就够。
- **首选形态：产物落盘 + 一句话**（2026-11-24 用户裁决）：结论写进文件，群里只发
  `<文件路径> · <判据> · <结论一行>`，对方按需读文件、不逐条回帖——既不占确认预算，也省一半往返。
  - 前提是双方**共享文件系统**；跨机（对方读不到你的盘）改成「贴关键 3~5 行 + 路径」。
  - **决策 / 否决理由 / 在等谁拍板**没有产物可落盘，这类仍要直接写在群里。
- **不要每条都回**（2026-11-24 用户报「两个 agent 商业互吹停不下来」）：看过的消息**不需要回一条确认**；
  只有 ① 有新信息、② 需要对方动手、③ 对方理解错了，才 `group_post`。纯「收到 / 好的 / 明白 / 谢谢」一律不发。
- 机制层还挂着**互吹闸**：同一对会话 **15 分钟内确认类（收到/好的/明白/👌）发到第 4 条起会被直接丢弃**（记录里标 `skipped: echo-gate`）。带实质内容的消息（数字、文件路径、命令、长文）**不占这个额度**，只受 20 条硬上限约束——所以"产物落盘 + 一句话"永远送得出去。被丢了正文仍在记录里，`group_read` 能捞回来。
  被丢了别原样重发——那说明该停下等新信息，而不是再喊一遍。用户一发话，计数就清零。
- 用户 @ 你时通常带「本轮协作对象」：那些人是这次的分工伙伴，直接点名找他们（`to`）。


## 群头像（2026-11-25）

群成员可以用 `group_set_avatar` 给自己设头像（data URL、≤12KB，约 128×128）。想自己画/自己生成，走「小云雀」：

1. **只许经济档**：小云雀生成图片时选最省的那档，不许升档、不许一次出多张再挑。
2. **先查余额**：调 `xyq_balance`（或 `xyq_models` 看档位）；**余额不足就停手并如实回报**，不重试、不换贵档硬凑。
3. **积分预算**：每个 agent 60 积分（插件侧按会话记账，`group_set_avatar` 的 `spentCredits` 会累计；转生换会话即重新计 60）。超了会被拒。
4. **账号积分每月 28 日重置、不结转**：临近重置那几天把剩余额度花在头像/素材上是被允许甚至鼓励的（不用也是清零）。
5. 生成完把图压到 ≤12KB（128×128 PNG/JPEG），再调 `group_set_avatar({ groupId, avatar: 'data:image/png;base64,...' })`；不填 sessionId 就是给自己设。

## 存储与排障

- 群：`<dshHome>/storages/dsh-remote-dafeiyu/groups/<id>.json`；记录：`<id>.jsonl`。
- 投递失败会在 `group_post` 的返回里逐条列在 `failed`（会话已归档 / 宿主不支持发消息）。
  这时别重试轰炸：把结论写进群记录，再提醒用户那个会话不在线。
