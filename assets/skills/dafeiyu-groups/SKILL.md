# 肥鱼拉群（dafeiyu-groups）

## 它是什么，不是什么

群是一层**给用户看的记录**：用户能在群面板里看到谁 @ 了谁、说了什么。
而你（agent）**看不到群里的整段消息**——插件只把你被 @ 的那条单独送进你的会话，
里面带「本轮协作对象」。所以：群里其他人的话你不知道，除非对方点名给你。

## 你什么时候会用到

- 收到「【入群通知 · 群名 · 群 id】」：你被拉进群了，名单在通知里；
- 收到「【群 群名 · 群 id · 来自 用户/某会话】」：有人 @ 你，正文 + 本轮协作对象都在里面。

## 三个动作

1. **把结论同步进群**：`group_post(groupId, text)` —— 只入记录，不打扰别人。
   想点名让谁看，加 `to: [对方短号或会话 id]`，这句话会**单独投给那几个人**。
2. **补上下文**：`group_read(groupId, limit=20)` —— 看最近记录（你别每轮都读，很占上下文）。
3. **建群 / 拉人 / 退群**：`group_create(name, sessionIds)`、`group_invite(groupId, sessionIds)`、
   `group_leave(groupId)`。

## 说话的分寸（重要）

- 每条 `group_post` 都可能进别人的上下文：**只说对方必须知道的**（接口变了、字段改名、谁在等谁）。
- 单条 4000 字上限；长内容写进文件、在群里给路径。
- 不确定要不要说就别说。群不是聊天室，是同步通道。
- 用户 @ 你时通常带「本轮协作对象」：那些人是这次的分工伙伴，直接点名找他们（`to`）。

## 存储与排障

- 群：`<dshHome>/storages/dsh-remote-dafeiyu/groups/<id>.json`；记录：`<id>.jsonl`。
- 投递失败会在 `group_post` 的返回里逐条列在 `failed`（会话已归档 / 宿主不支持发消息）。
  这时别重试轰炸：把结论写进群记录，再提醒用户那个会话不在线。
